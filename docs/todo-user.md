## 1단계 — 모든 가정의 뿌리 (이게 안 되면 나머지가 무의미)

### 1-1. 증권사 API 접속 가능 여부 확인

**왜 먼저인가.** 지금 저장소의 증권사 연동 코드는 **성공 호출 기록이 0회다.**
엔드포인트도 추정이고, AWS 서울이 데이터센터 대역이라 차단 여부도 모른다.
D-019 이후 모든 설계가 "API가 이렇게 생겼을 것"이라는 가정 위에 있다.

- [ ] 증권사 Open API 신청 → 앱키·시크릿 발급
- [ ] AWS 서울 리전에 **가장 작은 인스턴스** 한 시간 띄우기 (몇백원)
- [ ] 그 위에서 API 호출 1건 성공시키기 (종목 현재가 조회 정도)
- [ ] 결과 공유 — 성공/실패, 실패면 에러 메시지 그대로

**실패하면.** 집 PC나 다른 경로를 검토해야 한다. 서버를 본격 구축하기 전에 안다.

---

### 1-2. 증권사 서버 측 조건주문 지원 여부 확인

**왜 중요한가.** 무인 운용의 **최후 안전망**이다 (D-030).
Watchdog도 프로세스라 죽는다. 서버가 통째로 죽어도 증권사 서버는 살아 있다.
주문할 때 손절을 증권사 쪽에 걸어두면 내 시스템 생존과 무관하게 손실이 한정된다.

- [ ] API 문서에서 **자동 손절/조건주문(스탑로스)** 지원 여부 확인
- [ ] 지원하면 — 어떤 방식인지 (API 이름, 유효기간, 당일만인지)
- [ ] 미지원이면 — Claude에게 알려줄 것. **무인 운용 설계를 다시 짜야 한다**

---

### 1-3. API 제약 실측

- [ ] 호출 제한 (초당/분당 몇 건)
- [ ] 분봉 조회 깊이 (당일 전체? 과거 며칠?)
- [ ] 웹소켓 지원 여부, 동시 구독 한도
- [ ] 수급 데이터가 장 마감 후 언제 확정되는지

**용도.** 수집 규모(`collect.top_n`, `control_n`, `cohort_n`)와 크론 시각을 이걸로 정한다.

## 2단계 — 데이터 조달 (규칙 탐색 루프 전체의 전제)

### 2-1. 과거 분봉 확보 경로 찾기

**왜 중요한가.** 에이전트가 규칙을 만들려면 과거 데이터가 필요하다.
확보량이 **이 프로젝트의 시작 시점**을 정한다.
아무것도 없으면 앞으로 쌓는 수밖에 없어 첫 규칙까지 수개월이 걸린다.

- [ ] 증권사 API로 과거 분봉을 얼마나 받을 수 있는지
- [ ] 부족하면 다른 경로 (유료 벤더, 데이터 판매처 등) 조사
- [ ] 학습/검증/홀드아웃 3구간으로 나눌 만큼 확보 가능한지 판단
- [ ] 프로그램 매매 수급 포함 가능 여부

---

### 2-2. 호가 단위 표 확인

**왜 필요한가.** 체결 엔진이 쓴다. **틀린 표를 넣으면 모든 체결가가 조금씩 어긋나고
그 오차가 거래 횟수만큼 누적된다.** 그래서 임의 값을 넣지 않고 비워뒀다.

- [ ] 거래소 규정에서 가격대별 호가 단위 확인
- [ ] **코스피와 코스닥 각각** (다를 수 있다)
- [ ] `config.toml`의 `execution.tick_table`에 기입

---

### 2-3. 실제 수수료율 확인

- [ ] 증권사 약관에서 매수·매도 수수료율
- [ ] `config.toml`의 `cost.commission_buy`, `cost.commission_sell`에 기입
- [ ] 거래세는 법정 0.20%라 코드에 이미 있다. 채울 필요 없다

---

## 3단계 — 서버 구축 (1단계 통과 후)

### 3-1. AWS 기본

- [ ] 서울 리전(ap-northeast-2)에 작은 CPU 인스턴스 생성
- [ ] **약정 없이 온디맨드로** (검증 전에 1년 묶으면 접어도 비용이 나간다)
- [ ] SSM Session Manager 설정 — **인바운드 포트 0개**
- [ ] 아웃바운드 제한 (증권사·텔레그램·모델 API·패키지 저장소만)
- [ ] 시각 동기화(NTP) 확인

### 3-2. AWS 계정 보안 (서버보다 큰 위험일 수 있다)

- [ ] 루트 계정 MFA
- [ ] 액세스 키를 코드·깃에 넣지 않기
- [ ] **비용 알람 설정** — 키가 유출되면 마이닝 인스턴스가 떠서 청구서가 수백만원 나온다

### 3-3. 권한 분리 (자율 배포의 전제 — 이게 없으면 방어선이 없다)

- [ ] 계정 3개 생성 — `executor` / `hermes` / `watchdog`
- [ ] `executor`만 증권사 API 키 보유
- [ ] `hermes`는 DB 읽기만, `~/.hermes`만 쓰기
- [ ] `limits/` `holdout/`에 `hermes` 접근 차단
- [ ] **실제로 접근 시도해서 OS가 막는지 확인**

### 3-4. 백업

- [ ] 원자료 S3 동기화 또는 스냅샷 자동화
- [ ] **원자료는 다시 못 구한다.** 디스크가 날아가면 몇 달치 탐색 공간이 사라진다

### 3-5. 서버 밖 감시자

- [ ] 인스턴스 상태 알람을 AWS 바깥 경로로 받기
- [ ] **서버가 죽으면 Watchdog도 죽는다.** 죽었다는 사실은 밖에서 알려줘야 한다

## 값 채우기 (확인되는 대로)

**근거 없이 채우지 않는다.** 정할 때마다 Claude에게 알려주면 `context-notes.md`에 D-번호로 남긴다.
